Cubo de Datos de Gasto Comercial: Descripción volver a índice

Para la generación del cubo de datos de gasto comercial se reutiliza el vocabulario W3C Data Cube. Este vocabulario es una recomendación del W3C para la publicación de datos multidimensionales en la Web, lo que facilita su representación estructurada, interoperabilidad y reutilización. Además, este vocabulario es compatible con el estándar SDMX (Statistical Data and Metadata eXchange), ampliamente utilizado para el intercambio de datos y metadatos estadísticos entre organizaciones.
Como se muestra en la Figura 1, W3C Data Cube contiene varios conceptos y propiedades que permiten describir datos estadísticos en diferentes niveles de agregación. En este vocabulario, el modelo se organiza en torno al concepto de qb:DataSet, que representa un conjunto de datos que sigue una estructura definida mediante una qb:DataStructureDefinition y que se materializa a través de un conjunto de observaciones representadas mediante qb:Observation. Este vocabulario en concreto define una estructura de datos, representada por la instancia edintgast:DSD_CommercialExpenditure. Esta estructura agrupa todas las dimensiones y medidas necesarias para representar información sobre gasto comercial. Como ejemplo se define un conjunto de datos, es decir un conjunto de observaciones representado por la instancia ex:dataset/DS_CommercialExpenditure. Los componentes de una estructura de datos son los siguientes:
  • qb:DimensionProperty: componente que identifica las dimensiones de las observaciones, como la región administrativa de referencia, el sector temático, la actividad económica, el periodo de referencia o la nacionalidad. Las dimensiones suelen tomar sus valores de listas de códigos o clasificaciones, normalmente representadas mediante SKOS, o de otros recursos controlados.
  • qb:MeasureProperty: componente que representa el valor medido de los datos observados. En este cubo, las medidas corresponden al importe monetario total del gasto comercial y al número de transacciones.
Para definir estas dimensiones y medidas se reutilizan varios vocabularios de referencia:
  1. Vocabularios SDMX (Statistical Data and Metadata eXchange):
    • sdmx-dimension: se reutiliza como base para dimensiones estadísticas generales, especialmente mediante relaciones de especialización como edintdimension:refAdminRegion y edintdimension:refPeriod.
    • sdmx-measure: se reutiliza como base para las medidas del cubo, definidas como subpropiedades de sdmx-measure:obsValue.
  2. Vocabularios territoriales y temporales:
    • esadm: se reutiliza para indicar que la dimensión edintdimension:refAdminRegion puede tomar valores correspondientes a municipios, barrios o distritos.
    • OWL-Time: se reutiliza para modelar la dimensión temporal, estableciendo que edintdimension:refPeriod tiene como rango time:Interval.
  3. Listas de códigos SKOS:
    • La dimensión edintdimension:sector reutiliza como lista de códigos el esquema de sectores públicos publicado en datos.gob.es.
    • La dimensión edintdimension:economicActivity reutiliza una clasificación controlada de actividades económicas, como CNAE 2025 que ha sido transformado a una taxonomía SKOS.
El modelo del cubo de gasto comercial se muestra en la Figura 2, donde se presentan las dimensiones y medidas que lo componen.
La estructura del cubo de gasto comercial se define mediante la instancia edintgast:DSD_CommercialExpenditure, que agrupa todas las dimensiones y medidas del modelo. En este caso, la región administrativa de referencia, el sector, la actividad económica, el periodo de referencia y la nacionalidad se han definido como dimensiones. Como medidas, el modelo incluye el importe del gasto, que representa la cantidad monetaria total del gasto comercial realizado en un contexto determinado y el número total de transacciones realizadas.

A continuación, se describen los pasos necesarios para representar una observación concreta. **1) Definición del conjunto de datos y su relación con la estructura de datos:** Este ejemplo contiene un conjunto de datos, representado por ex:dataset/DS_CommercialExpenditure, que está vinculado a la estructura edintgast:DSD_CommercialExpenditure mediante la propiedad qb:structure.
**2) Identificación de las dimensiones y las medidas relevantes:** La estructura edintgast:DSD_CommercialExpenditure contiene las dimensiones y las medidas del cubo de gasto comercial. En este ejemplo se utilizan las dimensiones edintdimension:refAdminRegion, edintdimension:sector, edintdimension:economicActivity, edintdimension:refPeriod y edintdimension:nationality, junto con las medidas edintmeasure:expenditureAmount y edintmeasure:numberOfTransactions. Es importante señalar que la dimensión edintdimension:refPeriod tiene como rango time:Interval, por lo que el periodo de referencia debe representarse mediante una instancia explícita de intervalo temporal.
**3) Definición de una observación del conjunto de datos:** El último paso consiste en crear una instancia de qb:Observation y vincularla al conjunto de datos mediante la propiedad qb:dataSet. A continuación, se asignan los valores correspondientes a las dimensiones seleccionadas y a la medida de importe de gasto.
Esta observación indica que, en el municipio de Zaragoza, durante el intervalo temporal correspondiente a enero de 2025, el gasto comercial asociado al sector comercio, a una actividad económica concreta y a la nacionalidad española es de 125.430,75 y el número total de transacciones realizadas es 313 . Este ejemplo muestra cómo una única observación del cubo combina varios valores de dimensiones con unas medidas específicas para representar información sobre gasto comercial. Del mismo modo, la misma estructura puede reutilizarse para representar valores de gasto en otras regiones administrativas, periodos de referencia, actividades económicas, sectores o nacionalidades.
