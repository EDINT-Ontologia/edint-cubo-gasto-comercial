Commercial Expenditure Data Cube: Description back to ToC

The W3C Data Cube vocabulary is used to generate the commercial expenditure data cube. This vocabulary is a W3C recommendation for publishing multidimensional data on the Web, facilitating its structured representation, interoperability, and reuse. Furthermore, this vocabulary is compatible with the SDMX (Statistical Data and Metadata eXchange) standard, which is widely used for the exchange of statistical data and metadata between organizations.
As shown in Figure 1, the W3C Data Cube contains various concepts and properties that allow for the description of statistical data at different levels of aggregation. In this vocabulary, the model is organized around the concept of a qb:DataSet, which represents a dataset that follows a structure defined by a qb:DataStructureDefinition and is realized through a collection of observations represented as qb:Observation entities. This specific vocabulary defines a data structure, represented by the instance edintgast:DSD_CommercialExpenditure. This structure groups together all the dimensions and measures necessary to represent information regarding commercial expenditure. As an example, a dataset—that is, a collection of observations—is defined, represented by the instance edintgast:dataset1. The components of a data structure are as follows:
  • qb:DimensionProperty: a component that identifies the dimensions of the observations, such as the administrative region of reference, the thematic sector, the economic activity, the reference period, or nationality. Dimensions typically draw their values ​​from code lists or classifications—often represented using SKOS—or from other controlled resources.
  • qb:MeasureProperty: a component that represents the measured value of the observed data. In this cube, the measures correspond to the total monetary value of commercial expenditure and the number of transactions.
To define these dimensions and measures, several reference vocabularies are reused:
  1. SDMX (Statistical Data and Metadata eXchange) vocabularies:
    • sdmx-dimension: reused as a basis for general statistical dimensions, particularly through specialization relationships such as edintdimension:refAdminRegion and edintdimension:refPeriod.
    • sdmx-measure: reused as a basis for the cube's measures, defined as subproperties of sdmx-measure:obsValue.
  2. Territorial and temporal vocabularies:
    • esadm: reused to indicate that the edintdimension:refAdminRegion dimension can take values ​​corresponding to municipalities, neighborhoods, or districts.
    • OWL-Time: reused to model the temporal dimension, establishing that edintdimension:refPeriod has time:Interval as its range.
  3. SKOS code lists:
    • The edintdimension:sector dimension uses the public sector scheme published at datos.gob.es.
    • The dimension edintdimension:economicActivity reuses a controlled classification of economic activities, such as CNAE 2025, which has been transformed into a SKOS taxonomy.
The commercial expenditure cube model is shown in Figure 2, which presents the dimensions and measures that comprise it.
The structure of the commercial expenditure cube is defined by the instance edintgast:DSD_CommercialExpenditure, which groups all the dimensions and measures of the model. In this case, the reference administrative region, the sector, the economic activity, the reference period, and the nationality have been defined as dimensions. As for measures, the model includes the expenditure amount—representing the total monetary value of commercial expenditure incurred in a given context—and the total number of transactions carried out.

Example 1: Commercial expenditure amount by area, period, economic activity, sector, and nationality back to table of contents

This example represents data corresponding to the commercial expenditure amount in a given administrative region, for a specific reference period, broken down by economic activity, sector, and nationality.

The steps required to represent a specific observation are described below. **1) Defining the dataset and its relationship with the data structure:** This example contains a dataset, represented by edintgast:dataset1, which is linked to the structure edintgast:DSD_CommercialExpenditure via the property qb:structure.
**2) Identifying the relevant dimensions and measures:** The structure edintgast:DSD_CommercialExpenditure contains the dimensions and measures for the commercial expenditure cube. In this example, the dimensions edintdimension:refAdminRegion, edintdimension:sector, edintdimension:economicActivity, edintdimension:refPeriod, and edintdimension:nationality are used, along with the measures edintmeasure:expenditureAmount and edintmeasure:numberOfTransactions. It is important to note that the edintdimension:refPeriod dimension has a range of time:Interval; therefore, the reference period must be represented by an explicit instance of a time interval.
**3) Defining an observation in the dataset:** The final step involves creating an instance of qb:Observation and linking it to the dataset using the qb:dataSet property. Next, the corresponding values ​​are assigned to the selected dimensions and to the expenditure amount measure.
This observation indicates that, in the municipality of Zaragoza, during the time interval corresponding to January 2025, the commercial expenditure associated with the commerce sector, a specific economic activity, and the Spanish nationality amounts to 125,430.75, and the total number of transactions carried out is 313. This example shows how a single observation in the cube combines various dimension values ​​with specific measures to represent information on commercial expenditure. Similarly, the same structure can be reused to represent expenditure values ​​across other administrative regions, reference periods, economic activities, sectors, or nationalities.
